安全与路径访问规格

定义 root 边界、符号链接、隐藏规则命中和统一 404 行为。

1. 责任边界

security-spec.html 只定义路径解析、访问判定和错误响应策略。默认扩展名和默认隐藏规则归 config-spec.html 维护。

2. 路径处理流程

  1. 接收 URL path，进行标准 URL decode。
  2. 拒绝空字节和无法解码的路径。
  3. 将 path 作为相对路径拼接到 root。
  4. 使用 Path.resolve() 解析真实路径。
  5. 验证真实路径仍位于 root 的真实路径之下。
  6. 再执行隐藏规则、文件类型和目录访问判断。

3. 符号链接

允许符号链接，但只允许解析后仍位于 root 内的目标。越界符号链接在目录页不展示，直接访问返回 404。

4. 统一 404 策略

以下情况均返回 404，避免向调用者泄露文件是否真实存在：

  • 路径越出 root。
  • 路径命中隐藏规则。
  • 文件扩展名既不属于 direct，也不属于 rendered。
  • 符号链接目标越出 root。
  • 路径不存在。

5. 目录列表安全

  • 目录页只能展示未命中隐藏规则的目录。
  • 目录页只能展示 direct 或 rendered 文件。
  • 目录页不提示被隐藏条目的名称。
  • 目录页可以提示“部分条目已隐藏”的数量，但初版建议不显示数量，减少信息泄露。

6. 响应头

  • 所有响应建议添加 X-Content-Type-Options: nosniff。
  • rendered 页面必须添加保守 CSP。初版建议：default-src 'none'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; frame-src 'self'; media-src 'self'; object-src 'self'; base-uri 'none'。
  • direct HTML 不添加 CSP；初版不拦截页面自身行为，避免破坏远程预览。
维护约定：跨文档共享的默认值只在本规格中记录，其他文档引用本规格，避免重复维护。
