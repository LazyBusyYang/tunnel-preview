CLI 快速启动规格

定义 tunnel-preview 的一键启动体验、PATH 安装、阻塞式运行和自动端口选择。

1. 目标体验

CLI 的核心目标是远程开发时“一键启动”预览服务：用户进入任意项目根目录后，运行一个短命令即可阻塞式启动 server，并在终端看到可访问 URL。

cd /workspace/project
tunnel-preview
快速启动应尽量少设置参数。没有显式指定 root 时使用当前工作目录；没有显式指定端口时自动寻找可用端口并占用。

2. 安装与 PATH

项目应提供标准 Python console script，使用户可以把 CLI 加入自己的环境变量或 PATH。推荐入口命令为 tunnel-preview。

# 开发安装
uv pip install -e .

# 用户级安装示例
pipx install tunnel-preview

# 之后在任何项目根目录运行
tunnel-preview

文档应说明：只要 tunnel-preview 命令可被 shell 找到，就可以在远程开发机的项目根目录快速启动预览服务。

3. 阻塞式运行

默认运行模式是前台阻塞式进程，适合远程开发终端、tmux、Cursor/VS Code terminal 使用。

  • 启动后持续占用终端，直到用户按 Ctrl-C。
  • 收到 SIGINT / SIGTERM 时优雅关闭。
  • 终端输出当前 root、host、port、本地 URL 和可用于端口转发的提示。
Serving /workspace/project
Local URL: http://127.0.0.1:58231/
Press Ctrl-C to stop.

4. 端口选择

快速启动模式下，如果用户没有通过 CLI 或配置文件显式设置端口，程序应随机查找一个可用端口并立即绑定占用，避免端口探测和实际启动之间的竞态。

  1. 如果 CLI 指定 --port，使用该端口；不可用则启动失败。
  2. 如果配置文件指定固定端口，使用该端口；不可用则启动失败。
  3. 如果都没有指定端口，绑定 0 或等价机制，让操作系统分配可用端口。
  4. 启动后从 server socket 读取实际端口并打印。
配置默认值见 config-spec.html。实现时需要区分“配置默认端口”和“快速启动未显式设置端口”。快速启动应优先自动选端口，以减少远程开发冲突。

5. Host 选择

默认 host 仍由 config-spec.html 维护，当前策略偏安全：默认监听本机地址。远程开发通常通过 Cursor/VS Code 端口转发、SSH tunnel 或类似机制访问。

# 默认安全启动，配合端口转发使用
tunnel-preview

# 需要远程主机局域网可访问时显式指定
tunnel-preview --host 0.0.0.0

6. 参数设计

参数快速启动默认行为说明
PATH 参数或 --root当前工作目录允许 tunnel-preview /some/project，也允许 --root。
--host见 config-spec.html默认安全；需要外部监听时显式指定。
--port未显式设置时随机可用端口显式指定时不可用则失败。
--config按 config-spec.html 查找显式指定配置文件时不存在或非法则失败。
--page-size见 config-spec.html覆盖配置文件中的目录分页大小。

7. 推荐用法

# 最常用：项目根目录一键启动，自动找端口
tunnel-preview

# 指定目录，仍自动找端口
tunnel-preview /workspace/project

# 指定 host，仍自动找端口
tunnel-preview --host 0.0.0.0

# 指定端口，端口不可用则失败
tunnel-preview --port 5500

# 指定配置文件
tunnel-preview --config tunnel-preview.toml

8. 测试要求

  • 无参数时 root 为当前工作目录。
  • 无显式端口时可启动并打印实际端口。
  • 显式端口被占用时启动失败且错误清晰。
  • 显式 host 生效。
  • Ctrl-C 可正常停止进程。
  • console script 安装后可从 PATH 调用。
维护约定：CLI 快速启动体验由本规格维护；默认值仍引用 config-spec.html。
